기획의 중심은 유지

“가져와서, 확인하고, 믿을 수 있게 본다.”

기획안의 약속

  • 엑셀 거래를 미리 보고 승인 후 누적
  • 기간별 수익·지출·차액을 한곳에서 확인
  • 결제수단별 사용 현황과 암호화 백업

구현 결과

  • 가져오기 검토·중복 판정·사용자 승인
  • 대시보드, 거래내역, 분류, 결제수단 화면
  • 로그인, 운영 패키지, 암호화 백업·복원

표시 기준: 개인 금액·거래 내역·식별 가능한 값은 넣지 않았습니다. 화면 예시는 기능명만 사용합니다.

기획안과 달라진 점과 이유

핵심 흐름은 지키고,
안전성과 실제 사용성을 보강했다.

저장 방식

기획안의 “기기 내 저장” 표현과 달리, 승인 거래는 집 안 서버의 PostgreSQL에 저장. 원본 엑셀은 브라우저에서 읽고 서버로 보내지 않도록 구현. 저장 위치를 명확히 구분하기 위해.

가져오기 안전

단순 가져오기가 아니라 중복·미분류·오류 상태를 보여주고, 검토 후 승인된 신규 행만 반영. 기존 거래를 덮어쓰지 않도록.

분류 운영

경비 정산과 사용자 지정 분류 규칙을 추가. 실제 기록의 급여·경비 정산 구분을 조정할 수 있게 하되, 규칙 적용도 미리보기와 승인 후 반영.

계획에서 제외

금융상품 추천·시뮬레이션·연금·클라우드 동기화는 범위 밖으로 유지. 민감정보와 MVP 검증 범위를 우선.

기능 구현
v0.1.x가져오기·대시보드·조회·백업 흐름 구현. 개발 기록에 테스트와 합성 데이터 검증 기록.개인별 확인·수정 내용은 제공된 기록에서 확인되지 않음.
배포 준비
v0.2.0배포 패키지·백업·운영 문서 작성. 설정·HTTPS·로그 비밀값 부재 확인.운영 배포나 실제 데이터 반영을 승인한 기록은 확인되지 않음.
분류 규칙
v0.3.0경비 정산·사용자 분류 규칙·결제수단 종류를 추가하고 브라우저 동작 검증.개인별 확인·수정 내용은 발표자 확인 후 반영.
막힘 → 복구
v0.2.1메뉴 이동 때 빈 화면 발생. 원인: scrollTo의 Promise가 effect 정리 함수로 취급됨. effect를 블록 본문으로 바꾸고 회귀 테스트 및 6개 메뉴 이동 재확인.수정 결과는 개발 기록으로 확인. 개인의 직접 수정 여부는 확인 필요.

확인되지 않은 개인 행동은 사실처럼 쓰지 않았습니다. 발표 전 실제로 확인·수정한 내용을 여기에 덧붙일 수 있습니다.
